# كيف ينسق Neura النماذج والمهام

## دورة التشغيل

`neura-ai.desktop` يفتح `neura-ai`، الذي يفتح نافذة Qt WebEngine. النافذة تشغّل عملية API واحدة على منفذ loopback متاح وتتحقق من معرفها قبل عرض الواجهة. لا تقتل عملية موجودة على منفذ معروف. قفل مستخدم يمنع فتح نسخ متعددة؛ فتح الأيقونة مرة ثانية يعيد تنشيط النافذة.

`DesktopSettings` يحفظ اختيار مجلد النماذج والموارد تحت إعدادات المستخدم. يُنشئ المشغّل نسخة تشغيل من سجل YAML في مجلد بيانات المستخدم؛ لا يحتاج تعديل ملفات `/opt`. عند الإغلاق يوقف عملية الخادم التي أنشأها فقط.

## من الطلب إلى الرد

1. تستقبل API رسائل system/user/assistant وصورًا مضمّنة عند وجودها، وتتحقق من الحدود والمستوى.
2. يكتشف Router النية ويعيد `tier, model_id, reason, intent`. الاختيار اليدوي ملزم؛ fallback مسموح للتوجيه التلقائي فقط وبعد فحص البديل.
3. يقفل `NeuraLoop` دورة النموذج. عند تبديل الملف يُغلق القديم ثم يتحقق من التوافر والميزانية ويحمّل الجديد، ويحدّث Residency بعد النجاح.
4. يمرر `LlamaCppBackend` الرسائل إلى `create_chat_completion` وقالب GGUF. Vision يستخدم MTMD مع projector محلي.
5. يعاد الرد غير الفارغ مع model ID الفعلي و`finish_reason` وusage عندما تتوفر. البث يمر من مولّد native عبر طابور محدود؛ لا توجد محاكاة backend حرفًا حرفًا بعد انتظار الرد كاملًا.
6. تعمل المهلة والإلغاء بصورة تعاونية. لا يُبدّل النموذج أثناء تقييم native جارٍ؛ القفل يبقى حتى انتهاء العمل.

## المهام والنماذج

FAST يستخدم Gemma المحلي الذي تعرّفه Metadata بأنه Gemma 3 4B، وDAILY يستخدم Qwen3.5 9B. EXPERT وCODER يستخدمان ملف Qwen المقطّر نفسه مؤقتًا، مع تعليمات مناسبة للمهمة. وجود اسم Claude في اسم الملف المجتمعي لا يجعله خدمة Claude أو نموذجًا رسميًا منها. VISION يستخدم Qwen3VL وmmproj.

المحادثة العادية لا تحتاج مرورًا على كل النماذج. في مهمة إنشاء ملفات صريحة، تُمرر فاتورة JSON بين المراحل: طلب ومتطلبات وقيود → خطة اختيارية من EXPERT → ملفات من CODER → فحوص التطبيق → محاولة تصحيح واحدة عند الحاجة. كل مرحلة تسجل النموذج والتوقف والقياسات والمخرج الخام كنص أو JSON. تمرير الفاتورة ينفذه المنسق؛ لا توجد شبكة اتصال مستقلة بين الأوزان.

فحص Python/JSON والملفات والرموز المطلوبة فحص ساكن. `executed: false` و`behavior: not_run` مقصودان؛ لا يشغّل المنتج برنامجًا مولدًا بصلاحيات المستخدم ولا يستخدم درجة نموذج مراجع بديلًا عن اختبار قبول.

## الذاكرة والقنوات

رسائل المحادثة كاملة تصل إلى النموذج ضمن حدود السياق، وخزنة SQLite تحفظ الجلسات وتستعيدها. لا تُضاف حقائق من جلسات أخرى تلقائيًا إلى prompt، ولا توجد RAG أو Embeddings مفعلة بمجرد وجود ملف nomic في القرص.

Telegram عميل HTTP لنفس API. لا ينشئ ModelPool ولا يحمّل أوزانًا مستقلة. تقييد معرف المستخدم يسبق أي استدعاء API. تشغيل Telegram يتطلب اعتمادياته ورمز المستخدم صراحةً؛ لم يُرسل اختبار النشر رسائل حقيقية.

## حدود الأدوات والصوت

الأدوات المنفذة محدودة بالبحث الاختياري ومسودة بريد. Terminal وGit وإرسال البريد معطّلة، ولا توجد موافقات شكلية تدعي تنفيذًا لم يحدث. `/skills` يعلن هذا السجل المحدود.

STT يحتاج whisper.cpp CLI وملف GGML وffmpeg، وTTS يحتاج Piper CLI وصوت ONNX مع JSON. ملفات Whisper/Kokoro وحدها لا تجعل الصوت جاهزًا. عند غياب المكونات تعرض API عدم التوفر ويُعطل زر التسجيل.

## التحديث

المحدّث يقرأ إصدار المستودع المحدد، ويقبل حزمة Arch المطابقة للنسخة والمعمارية وSHA256 التي أعادها GitHub. يتم التنزيل كالمستخدم. عند التثبيت يطلب Polkit صلاحية إدارية للمساعد المحدد، الذي يعيد قراءة الإصدار من GitHub ويُنشئ نسخة مملوكة للجذر ويتحقق من البصمة وهوية الحزمة قبل pacman. لا يثق بملف قابل للتعديل في مجلد التنزيل أثناء عملية التثبيت. لا تُلمس مجلدات النماذج والمحادثات ضمن معاملة تحديث التطبيق.
