أُعيد تحميل `Qwen2.5-Coder-14B-Q4_K_M.gguf` واستُخدم formatter والـtokenizer الفعليان مع نص الرسائل المسجّل كاملًا، بما فيه المصدر والخطة والعقود. لم يُستنتج أي عدد توكنات من عدد المحارف.

## ما تغير في التنفيذ

- `LlamaCppBackend.measure_messages` يعترض نداء formatter قبل التوليد لقراءة قائمة token IDs النهائية، ويرفض formatter غير المدعوم بدل تقدير عدد المحارف. يعد `CancellableLlama.generate` توكنات الطلب والخرج الأصلية ويسجل المهلة والحد المطلوب والحد الفعلي وسبب النهاية. يستعيد الاعتراض المؤقت حالة method الأصلية دون دورة مرجع جديدة.
- `BoundedEditor.generate` يعيد استخدام `InvoiceOrchestrator` والمنسق المقيم. التخطيط إلزامي قبل الإنشاء وكل تعديل مولّد. إذا لم يتسع مصدر التخطيط كاملًا تُعلن الخطة صراحة استخدام inventory وبصمات، ثم تُرسل جميع أجزاء المصدر المختار لعمليات الملفات المقاسة؛ لا يُقطع المصدر بصمت.
- كل `FilePatch` مرتبط بـ`base_revision` و`path` و`source_sha256`. يجب أن تظهر `before` مرة واحدة فقط وفي الجزء المرسل. المرساة المفقودة أو المكررة أو المصدر القديم يسبب رفضًا. `apply_exact` يعمل على نسخة مرشحة في الذاكرة.
- الأقسام `css_rules` و`script_code` و`html_fragment` تملك أغلفة HTML يضيفها الخادم عند حدود دقيقة وفريدة. لا يستطيع الرد اختراع موضع إدراج أو استبدال الملف القائم عبر `new_content`. طلبات إضافة عناصر HTML تستخدم أقسامًا منظمة؛ إعادة تصميم مرئية تُبقي HTML والسلوك وتستخدم CSS.
- تُقسّم الملفات عند الحاجة إلى عمليات محدودة داخل **المهمة نفسها والخطة نفسها**. الحدود الحالية:8 عمليات كحد أقصى،384 حدًا أدنى محجوزًا لكل عملية،3072 توكن خرج ابتدائيًا و1024 لمحاولة إصلاح واحدة بالنموذج. المخطط له768 منفصلة. تخصم الميزانية من usage الفعلي، وعند غيابه تُخصم الميزانية المطلوبة كاملة احترازيًا. لا تعني مجموعة الحدود المطلوبة أن كل مكالمة استهلكتها كلها.
- `ProjectJobs._generate` يعيد فحص مراجعة وبصمات **جميع** ملفات الأساس، يجمع المرشح مع الملفات غير المعدلة، ثم يجري الفحص الساكن والحفظ البنيوي والمعاينة المعزولة. بعد نجاح الجميع فقط يستدعي `ProjectStore.commit` مرة واحدة لترقية الملفات والإيصال والفهرس؛ لا توجد ترقية جزئية متعددة الملفات.
- `length` أو JSON ناقص أو عقد غير صحيح أو مرساة غير فريدة تُرفض قبل الترقية. الإصلاح نفسه مقاس ومحدود بمهلة المهمة و1024 توكن؛ إذا لم يتسع لا يُقص مصدره. يمكن إجراء تصحيح CSS حتمي من قياسات contrast ثم إعادة الفحص دون توكنات نموذج إضافية، بحد تمريري تصحيح ومحاولة نموذج واحدة.
- متطلبات Login/theme المأخوذة من طلبات المستخدم المقبولة أصبحت إلزامية في المعاينة. لا يكفي وجود زر؛ يجب تهيئة التبديل وتغير خلفية أسطح المحتوى المرصودة فعليًا. لا يثبت ذلك تكافؤ كل سلوك للموقع أو جودة جمالية كاملة.
- بقيت تسوية بطاقات المحادثة مع الحالة الدائمة عند النهاية والعودة والاستعادة. أُضيف قفل مشترك لقراءة `_row` على اتصال SQLite؛ التخطيط والإلغاء والمجدول الواحد والسياسات الأصلية محفوظة.

## إصلاحات إضافية كشفتها مراجعة الدليل الفعلي

لقطة `d12e07c/cpu-preserve-2` اجتازت checker القديم، لكن مراجعة `turn-4.png` كشفت نصًا أسود على خلفية داكنة. أُعيد تشغيل ملفاتها المحفوظة نفسها في تفضيلي light/dark، ففشلت القراءة والتبديل في dark. لذلك **لا يعد checker pass القديم دليل Gate A**. السبب أن إطار التطبيق يورث `color-scheme:dark`، بينما كان parent الفحص لا يحدد ذلك. أصبح الفحص يعيد تحميل المرشح في light وdark، ويؤكد `matchMedia` في الصفحة المعزولة، ويفحص480/1280 والتبديل في كل بيئة. وأصبحت إصلاحات الألوان داخل `@media` الموافق لكل مجموعة قياسات. يختار toggle العنصر المرئي، بما فيه رابط `href="#"`، بدل استبعاد رابط يعمل أو نقر عنصر مخفي سابق.

في لقطة `4ea6286/preserve-1` حدث `length` جديد عند1536 توكنًا: الطلب2538 والسياق4096 والحد المطلوب=الفعلي1536؛ **لا يوجد clipping صامت في هذه المكالمة**. النص الخام كرر قواعد theme-toggle حتى الحد. لذلك عُدّل خرج CSS native إلى قائمة لا تتجاوز6 قواعد ولكل منها6 خصائص. يركّب الخادم CSS من `selector/declarations/scheme`؛ يرفض التكرار والتجاوز وحقن خصائص إضافية. يبقى raw CSS القديم مقروءًا للتوافق، لكن grammar native الجديدة تختار القائمة أو null فقط. لا يُقبل النص المقطوع ولا تزداد الميزانية.
