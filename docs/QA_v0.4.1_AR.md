# تقرير التصحيح المحلي 0.4.1

التاريخ: 29 أكتوبر 2026، الرياض. أُنجز التنفيذ والبناء والتحقق محليًا؛ لم تُنشر 0.4.1 أو تُثبّت فوق نسخة المستخدم أثناء المهمة.

## السبب المؤكد والإصلاح

كانت مطابقة أوامر المحادثة في `web/skills.js` محدودة بعبارات مباشرة، ففشل طلب «هل يمكنك ان تفتح لي موقع youtube» وانتقل إلى نموذج المحادثة. ملفات النسخة المثبتة المتأثرة تطابقت مع مصدر 0.4.0. أصبح النص الجديد يمر عبر `web/chat.js` ثم `/chat/dispatch` و`src/core/chat_dispatch.py` إلى مهارات سطح المكتب القائمة. التنفيذ اليدوي يستخدم المنفذ نفسه، وتبقى التحقق والصلاحيات في الخلفية. لا تُمرر مخرجات النموذج أو المحادثة المسترجعة إلى منفذ الإجراءات.

كانت إجراءات المحادثة عناصر منفصلة في حاوية flex عمودية فتمددت. جُمعت في `#chat-actions` وأُعيد بناء CSS. وكان `finalize` يدعم أسوار الكود فقط؛ أصبح يعرض Markdown بمحلل محلي مثبت الإصدار وشجرة عناصر مسموحة، مع تعطيل HTML والصور والروابط الخطرة.

كانت مساحة المبرمج موجودة. أُصلح ربط نتيجة الإنشاء في المحادثة بالمشروع والمهمة نفسيهما، وتحديث اللقطات القديمة، ووضع علامة الانشغال قبل أول انتظار غير متزامن. لم يُستبدل مسار Invoice أو إدارة النماذج أو حفظ المشاريع.

## الملفات والمسار

| المسار | التغيير |
|---|---|
| `src/core/chat_dispatch.py` و`src/backend/chat_api.py` | تفسير عربي/إنجليزي محافظ، توضيح الهدف الملتبس، سجل دائم لمنع إعادة التنفيذ، مخططات طلبات صارمة |
| `src/backend/api.py` و`skills_api.py` | تسجيل المسارات المحمية ومشاركة منفذ المهارات وتقديم ملفات الواجهة بقائمة مسموحة |
| `src/tools/desktop_skills.py` و`src/desktop/paths.py` | فرض التعطيل والتوافر والصلاحيات في الخلفية وإظهار أخطاء محددة |
| `web/chat.js` و`web/skills.js` و`web/workspace.js` | الإجراء قبل الاستدلال، مشاركة التنفيذ اليدوي، مشروع واحد من الطلب، تحديث ملفات المهمة، حفظ السجل دون تنفيذ تاريخي |
| `web/index.html` و`input.css` و`styles.css` | شريط مدمج متجاوب وإتاحة لوحة المفاتيح وربط العرض الجديد |
| `web/markdown.js` و`web/vendor/` | Markdown آمن محلي، نصوص الكود مهربة، روابط HTTP(S) فقط ورخص المكتبات |
| `tools/build_web_assets.mjs` و`package*.json` و`.gitignore` | بناء المحلل وCSS وتضمينهما في المصدر والحزمة |
| `src/core/project_store.py` والاختبارات وREADME وملاحظات الإصدار | أسئلة غرض المشروع، انحدار وتوثيق وإصدار محلي 0.4.1 |

الإجراءات المتاحة من المحادثة: فتح موقع، بحث YouTube والويب، فتح Brave أو تطبيق مثبت، فتح ملف أو مجلد مختار، وفتح مجلد مشروع محفوظ. طلب الإنشاء يفتح مساحة المبرمج، وأسئلة لغة المشروع وغرضه تستخدم الفهرس. الشرح والنفي والاقتباسات والكود لا تُنفذ كأوامر. التعذر يُعرض كخطأ إجراء ولا يُخفى برد من النموذج.

## التخزين والحدود

المشاريع العادية في `~/.local/share/neura-ai/workspace/`، وتُفتح من المشاريع المحفوظة. الفهرس وقاعدة البيانات في مجلد بيانات Neura. المعاينة المحمولة تستخدم `~/.local/share/neura-ai-preview/` وإعدادات منفصلة ولا تنسخ رموز API أو صلاحيات المستخدم. اختبارات المهمة استخدمت بيانات QA مستقلة.

بقيت الأوزان في `/opt/neura-ai/models` دون نقل أو تضمين في الحزمة، ولم يُحذف `Downloads/ai`. لم تُنفذ Python أو shell أو أدوات بناء مولّدة. المشاريع المحتاجة خادمًا أو بناءً لا تحصل على معاينة موقع ثابت. التفسير حتمي ومحدود بالعبارات المدعومة، وليس فهمًا شاملًا لكل صياغة.

عند توقف التطبيق أثناء إجراء غير مؤكد، تُعرض النتيجة غير المؤكدة ولا يُعاد التنفيذ تلقائيًا؛ لا ضمان exactly-once على مستوى نظام التشغيل. قبول تشغيل Brave لا يثبت تحميل الصفحة أو قراءتها. اختبار النموذج الحقيقي على CPU وليس قياس GPU، واختبار زر واحد لا يضمن جودة كل موقع مولّد. تبقى النسخة المثبتة 0.4.0 حتى تطبيق التحديث صراحةً. التحديث داخل التطبيق لن يعرض 0.4.1 قبل نشرها في GitHub Releases.
