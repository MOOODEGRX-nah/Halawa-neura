# WEB B0/B1 — وصفة CV عربية محلية

تغيير مستقل بعد مرحلة الحماية. يحتوي الكتالوج الصغير مهارة واحدة مدعومة `prepare_static_cv`، ووصفة `arabic_cv_v1`. لا توجد Figma/Canva أو تنزيل قوالب أو مهارات ينشئها النموذج، ولم تبدأ B2.

اطلب من المحادثة: «برمج لي موقع سيرة ذاتية عربي محلي يعمل بدون إنترنت». بعد اعتماد نية إنشاء مشروع من نص المستخدم، يختار `ChatDispatcher` وصفة واحدة من قائمة ثابتة عبر سجل `DesktopSkills` الموجود وصلاحياته ومخططاته. الكلمات المنفية والاقتباسات والشرح لا تمنح تنفيذًا. طلب CV العام يبقى على المسار العام العامل؛ الاختيار الآلي للوصفة يتطلب دلالة عربية/محلية/offline صريحة. الطلبات ذات React أو backend أو أسماء ملفات تتعارض مع الوصفة لا تُجبر على قالب آخر. الاختيار لا يفتح جهازًا ولا يشغل كودًا ولا يدّعي إنشاء ملف؛ نتيجة السجل `selected` فقط، ثم ينشئ `ProjectJobs` المهمة الحقيقية الأصلية مرة واحدة دون إعادة كتابة الطلب.

المهارة موجودة في Settings الحالية ويمكن تعطيلها؛ لا تبويب دائم جديد. كتالوج `/skills` يبين الإتاحة والمخطط والحدود وبصمة الوصفة. الإسناد إلى الوصفة لا يمنح صلاحيات سطح المكتب ولا cloud. API المحلي يبقى محميًا بمصادقة Host/Origin/token.

`web_recipes.py` يعرّف تعليمات محدودة وملفات مطلوبة `index.html`, `style.css`, `script.js`. هذه ليست ملفات موقع ثابتة تُنسخ نيابة عن النموذج: المخطط المحلي يضع الخطة والمبرمج المحلي يولد الملفات الفعلية. الوصفة تطلب RTL وعناوين عربية وبيانات placeholder واضحة، وروابط محلية متطابقة، وزر `cv-font-toggle` بعنوان ثابت لتكبير خط فقرات `cv-content`. لا تبعيات أو imports أو موارد خارجية أو تخزين متصفح. سياسة CSP والعزل الموجودة تبقى قائمة.

فحص المصدر مستقل عن ادعاء النموذج: أسماء الملفات، مراجعها، لغة/اتجاه الصفحة، هويات التحكم وقيود الموارد. فحص Qt المعزول يضغط زر الخط مرتين، ويتحقق من تغير حجم خط فقرة فعلية ومن رجوعه ومن بقاء المحتوى وaria-state، في عرضي 480/1280 ومخططي ألوان light/dark. تغيير aria وحده لا يكفي. تبقى فحوص theme، النصوص، التحكم، contrast، revision/hash، والرفض المحدود والترقية الذرية. لا تنفيذ لبرامج مضيفة أو تثبيت تبعيات.

تُحفظ هوية الوصفة/version/hash كمنشأ إنشاء صغير في ميتا المشروع تحت `NEURA_DATA_DIR/workspace`. اللغة والملفات والحالة تأتي من الملفات المحفوظة نفسها. لا تعد الميتا ضمانًا للسلوك الحالي. التعديلات اللاحقة تعيد قراءة المصدر وتحمل العقد نفسه وتفحص زر الخط أيضًا؛ تغير عقد الوصفة يتطلب مراجعة توافق، ولا يطبق بصمت. يُربط job ببصمة العقد عند دخوله، ويُرفض استئناف انتظار بعقد آخر. حفظ يدوي لاحق يبقي منشأ الوصفة ويعيد فحص المصدر العام؛ لا يختلق نجاحًا سلوكيًا قديمًا.

فحوص المنطق الصناعية في `tests/regression/test_web_recipes.py`، وعينات المتصفح الثابتة في `tools/qa_web_recipe_browser.py` منفصلة عن استدلال composer الحقيقي. السيناريو الجديد في `tools/qa_accuracy_composer.py --workflow web-recipe --real-model` ينشئ CV من الطلب الأصلي ثم يضيف theme ثم يعيد طلب التحسين الأصلي، ويتوقف إن فشلت مرحلة سابقة. لا يعتبر نتيجة fixture أو زر ظاهر إثباتًا لتوليد حقيقي. سجل أدلة هذه المرحلة في `outputs/web-b01-20261112` خارج ملفات التطبيق، ويحدد اللقطة والنتائج الفعلية والقيود.

المرشح الحقيقي الأول أغفل `type=button`، ثم أعاد إصلاح النموذج جزءًا خاطئًا من المستند دون إصلاح السمة؛ رُفض الاثنان ولم يُحفظا. أضيف إصلاح شكلي محدود: عند هذا الخطأ المحدد فقط، يحدد parser زر الوصفة الفريد وموضع وسم بدايته، ويربطه بـ`RepairTargets` وبصمات كل المرشح والمراجعة/job/project، ثم يضيف السمة المفقودة فقط. لا يصلح هدفًا مكررًا أو سمات متضاربة أو خطأ آخر، ولا يستخدم fuzzy matching. يبقى ضمن محاولات المهمة ومهلتها، ويعاد بعده فحص المصدر والمتصفح. تصحيح contrast يبقى مستقلاً مبنيًا على قياس renderer؛ لا يرفع العدد المحدود لمحاولات النموذج. مصدر هذا التصحيح موسوم `model_called=false`، ولا يُنسب إلى توليد النموذج.
