# حماية الموارد وRX 580

هذا تغيير مستقل يأتي بعد إصلاح الطلبات المركبة. لا يثبت تشغيل لعبة فعلية أو تحسن FPS، ولا يغلق فحص الرؤية N093 أو KDE أو التحديث الإداري.

الإعدادات موجودة في نافذة الإعدادات الحالية تحت «حماية الموارد أثناء اللعب والأحمال الخارجية». Auto هو افتراضي سطح المكتب الجديد؛ Normal وProtected اختيارات يدوية. لا تتغير ملفات إعدادات النسخة المثبتة عند تطوير المصدر. CLI القديم يبقى Normal ما لم يحدد ملفًا صريحًا. ملف المستخدم canonical هو `NEURA_DATA_DIR/resource-protection.json`، وله مخطط `ProtectionConfig` في `src/core/resource_policy.py`. مثال قابل للمراجعة في `configs/resource-protection.example.json`؛ اختر هوية البطاقة ومجلد الأوزان قبل استعماله. لا يفترض المثال وجود وزن أو يحمّله.

## الكشف وحدوده

`resource_detection.py` يفحص هوية PID ووقت إنشائه، والاسم/المسار الدقيق، وSteamAppId/SteamGameId، ومسار اللعبة/الآباء. Steam وLutris وHeroic وWine وحدها ليست لعبة. العمليات المتعددة والأطفال في مجلد تثبيت اللعبة مدعومة. القواعد والاستثناءات دقيقة، لا أوامر shell ولا تعليمات صادرة من النموذج. فقدان قراءة عملية لعبة مع بقاء هويتها يحتفظ بالحماية بدل افتراض خروجها.

تستخدم الأحمال مجهولة الهوية CPU الفعلي وعدّادات DRM engine لكل عميل مع PCI للبطاقة الأساسية. تُستبعد عمليات Neura المسجلة وواجهة التطبيق المعروفة وعمليات compositor المعروفة؛ التطبيقات التي يفتحها المستخدم عبر المهارات ليست عمال Neura. VRAM ليست دليل نشاط. قياس النواة الساخنة حد أدنى محافظ: يُطرح وقت جميع العمال المستبعدين من كل نواة، وقد يفوت ضغط خارجي متزامن. GPU المقروء حد أدنى أيضًا؛ نقص التغطية لا يثبت انتهاء ضغط سبق رصده. القيم غير المتاحة تعرض مجهولة. الفحص محدود 2048 عملية و8192 fdinfo لكل عينة؛ ليس ضمان اكتشاف كل محرك أو لعبة.

فُكّت ملفات HalawahomDesk 2.0.1 المثبت محليًا للقراءة فقط وفُحصت `linux/monitor-apps.js` و`linux/ipc.js` و`linux/desktopapps.js` وREADME. تتعلق بمشاركة النوافذ والأجهزة وIPC داخلي لـElectron؛ لم يُعثر في الملفات المفحوصة على مصدر موثق لهوية لعبة أو ضغط محلي يمكن اعتماده. لم تُنسخ شيفرته ولم تُخترع واجهة اتصال، وليس اعتمادًا مطلوبًا.

## حدود التنفيذ

`NeuraLoop` يبقى مالك دورة حياة نموذج واحد. عند تغيّر الملف يزداد epoch، فتتوقف مكالمات النموذج القديمة تعاونيًا وتنتظر إزالة الأوزان حدًا آمنًا تحت القفل الموجود. لا ترحيل مباشر لـKV. المهمة التي بدأت تتوقف ببطاقة إلغاء تبين السبب وتحتفظ بآخر مراجعة؛ لا إعادة تنفيذ تلقائية أو ترقية جزئية. المرشح الكامل الذي انتهى استدلاله يمكن التحقق منه وحفظه دون استدلال إضافي. أي إصلاح لاحق يجب أن يطابق epoch الأصلية.

الدور المحمي يحتاج إسنادًا صريحًا، بما فيه المخطط Expert والمبرمج Coder. تُفحص الأوزان، السياق/KV، buffers والاحتياطي، ثم الذاكرة الحرة للبطاقة المختارة قبل التحميل. البطاقة تُربط بـPCI/vendor/device ثم تعداد backend الحالي؛ الأجهزة المتساوية السعة التي لا يمكن ربطها بأمان تُرفض بدل تخمين الهوية. `split_mode=0` يمنع توزيع الأوزان بين البطاقتين. 14B والمخطط 9B لا يصبحان مناسبين لـ8GB بمجرد تغيير اسم الجهاز؛ المهام التي لا تتسع تنتظر مع السبب ضمن مهلة الأصلية. خيار CPU بديل منفصل وصريح مع فحص RAM، وليس بديلًا صامتًا. لا يُغلق أي تطبيق لتوفير الذاكرة.

`WorkerLimits` يختار CPU منطقيًا واحدًا من كل نواة فعلية مميزة ضمن قيود العملية وcgroup، ويقيد العمال المسجلين والخيوط الأصلية المكتشفة عند التحميل والمساعدات الحالية والجديدة. لا يقيّد اللعبة، ولا يدعي حصرية الأنوية. يحفظ affinity الأصلية، ويحترم تضييقًا خارجيًا مرصودًا. nice يُطبق فقط إذا أمكن استعادته وفق RLIMIT_NICE، وإلا يظهر عدم تطبيقه. HTTP/UI يبقيان مستجيبين. مساعدة داخلية تُنشأ تحت النطاق المقيد قبل exec وتُسجل؛ تشغيل تطبيق مستخدم لا يُسجل كعامل.

الأدوار planner/coder/chat والرؤية المتوافقة تمر عبر المنسق نفسه. الرؤية تحتاج projector متوافقًا وفحصًا حقيقيًا مستقلًا. Whisper CLI لا يملك مهايئ GPU ثانوي موثّقًا هنا: محجوب أثناء الحماية. Piper وffmpeg المستخدمان CPU عبر مساعد مسجل؛ لا يُدعى التحقق من إخراج صوت أو embedding غير موجود. لا توجد استدلالات سحابية أو تنزيل/تثبيت آلي.

## الانتظار والأمان والبيانات

`ProjectJobs` يحد جميع المهام غير النهائية إلى خمس (عامل وأربع منتظرة). المهمة المحجوبة تبقى queued وسببها متاح للبطاقة. مهلة الانتظار محفوظة دون تجديد عند إعادة الفتح. فقط انتظار لم يبدأ التخطيط/التوليد يستأنف بنفس job ID بعد restart؛ تُحذف علامة الاستئناف قبل الاستدلال. المهمة الملغاة أو منتهية المهلة لا تولّد ملفات. إقلاع جديد يطابق حالة المنسق الفعلية، ولا يستعيد ادعاء نموذج محمّل من سجل سابق.

`GET /resources` و`POST /resources/config` لهما نفس token وHost/Origin وقيود API المحلية. إعدادات نموذج أو محتوى معاينة لا تمنح أذونات. المراقبة تعرض السبب والملف المطلوب والتأكيد الفعلي والجهاز والنموذج والأنوية وحالة الانتظار. تطبيق سياسة توجيه مع عدم وجود نموذج محمّل موضح صراحة، وليس ادعاء نجاح الاستدلال.

تبقى عقود الميزات والتخطيط الإلزامي والرفض المحدود والتحقق من المراجعات والبصمات والترقية الذرية كما هي. تسجل مراحل التخطيط والتوليد `resource_profile` مع native limits والجهاز، وتحتفظ المحاولة بإثبات الملفات والمعاينة.

## التحقق

فحوص الحدود الصناعية في `tests/regression/test_resource_protection.py` منفصلة عن التجارب الحقيقية. `tools/qa_worker_limits.py` يختبر CPU داخل عملية QA فقط. `tools/qa_accuracy_composer.py --resource-config <explicit-file>` يختبر المحرر الفعلي بالملف المختار؛ الوضع الافتراضي لهذا الاختبار Normal صريح للحفاظ على قابلية التكرار. استعمل `--real-model` فقط عند عدم وجود محرك Neura آخر، وبملف بيانات معزول.

سجل الأدلة الجاري: `outputs/rx580-evaluation-20261111` خارج ملفات التطبيق. لا يُدعى نجاح اختبار لم تُسجل نتيجته. تجربة Steam/Proton فعلية وقياس FPS/frametime تتطلب لعبة فعلية وسيناريو ثابتًا قبل/بعد مع مراعاة تطبيقات المستخدم؛ الاختبارات الصناعية لا تستبدلها.

المسارات القديمة المستقلة `src/neura_core.py` و`src/memory.py` و`src/vision.py` و`src/stt.py` و`src/speculative.py` ليست مسار سطح المكتب الحالي، ولا تدخل ضمن إثبات الحماية. تحتوي تحميلًا مباشرًا/تجريبيًا للأوزان، وبعضها يفترض أرقام GPU قديمة؛ تشغيلها يدويًا خارج التطبيق الحالي غير مدعوم بهذا الملف ولا يجوز وصفه بأنه يحترم الحماية. لم تُستبدل هنا بمحركات جديدة ولم تُعتبر memory/RAG عاملة في الواجهة الحالية.
