# تثبيت وتشغيل Neura AI

الهدف هو استخدام تطبيق من قائمة التطبيقات، مع إعداد النماذج وتحديث التطبيق من نوافذه.

## للمستخدم

1. ثبّت حزمة Linux من [GitHub Releases](https://github.com/MOOODEGRX-nah/Halawa-neura/releases/latest). يمكن استخدام الأمر الموجود في README مرة واحدة، أو تنزيل ملف `neura-ai-bin-<version>-1-x86_64.pkg.tar.zst` وتثبيته بمدير حزم Arch.
2. افتح **Neura AI** من قائمة التطبيقات. لا تشغّل API في طرفية أخرى.
3. اختر مجلد الأوزان من **الإعدادات والنماذج** إن لم يُكتشف تلقائيًا. لا تحتاج تغيير الشيفرة أو ملفات YAML.
4. اختر **تلقائي** للمحادثة أو ثبّت مستوى محددًا. التحميل الأول قد يستغرق وقتًا حسب النموذج والبطاقة.
5. افتح **التحديثات** داخل التطبيق للتحديث التالي. مصادقة النظام تخص تثبيت حزمة النظام؛ لا ترسل كلمة المرور إلى التطبيق أو GitHub.

يمكن استخدام `paru -S neura-ai-bin` بعد نشر الحزمة في AUR. ملفات AUR مجهّزة في Releases، لكن تسجيلها هناك خطوة مستقلة لم تتم بعد.

## متطلبات النظام

CachyOS/Arch x86_64 ومعالج يدعم AVX2، وPython 3.14 وQt6 WebEngine وتعريف Vulkan. يثبت pacman اعتماديات النظام المعرفة داخل الحزمة. لا يتضمن التطبيق أوزان النماذج. تعريف AMD المناسب هو `vulkan-radeon`؛ بطاقات أخرى تحتاج تعريف Vulkan الخاص بها. وضع CPU متاح من الإعدادات ولا يُختار بصمت عند فشل GPU.

الحزمة مرتبطة بإصدار Python ABI الحالي، وتصرّح بالحدود `>=3.14` و`<3.15`. عند انتقال التوزيعة إلى ABI جديد يحتاج الإصدار الثنائي إعادة بناء؛ لا يُدّعى أن مكتبات native قديمة تعمل على كل Python مستقبلي.

## الملفات في الإصدار

- `neura-ai-bin-<version>-1-x86_64.pkg.tar.zst`: حزمة تثبيت وتحديث pacman.
- `neura-ai-<version>-linux-x86_64.tar.zst`: ملفات runtime المستخدمة في حزمة AUR.
- `neura-ai-bin-<version>-aur.tar.gz`: `PKGBUILD` و`.SRCINFO` ببصمة runtime الفعلية.
- `SHA256SUMS.txt`: بصمات الملفات.
- `install.sh` و`install.py`: مثبت GitHub لأول مرة.

الحزمة تحتوي المحرك واعتماديات Backend. Qt وNumPy ومكتبات النظام تأتي من مدير حزم التوزيعة. أوزانك وإعداداتك ومحادثاتك تبقى خارج `/opt/neura-ai`.

## البناء من المصدر للمطور

تثبيت متطلبات Backend والاختبارات في `requirements-dev.txt`. محرك Vulkan منفصل في `requirements-inference.txt`. للتشغيل من المصدر يحتاج مفسّر الواجهة PySide6 وQt WebEngine، ويشغّل `neura-desktop.py` النافذة والخادم تلقائيًا. `start-neura.sh` مسار تطوير للـ Backend وليس طريقة تشغيل النسخة المثبتة للمستخدم.

يستخدم بناء Linux في Actions صورة Arch، وCMake مع Vulkan و`GGML_NATIVE=OFF`، ثم يشغّل makepkg كمستخدم غير مميز. يتطلب `tools/build_linux_release.py` مجلد vendor صريحًا، ولا ينسخ البيئة الشخصية أو الأوزان أو `.env`. الناتج الثنائي يُرفع إلى Releases بدل وضع المكتبات الكبيرة داخل Git.

لإصدار جديد: عدّل `VERSION`، وحدّث ملاحظات الإصدار، وادفع التغيير إلى `main`. لا يعيد البناء نشر أصول إصدار مستقر موجود أو استبدالها بصمت. انتظر نجاح Actions ووجود الأصول قبل الإعلان عن رابط التنزيل.

## إعادة محاولة التثبيت

المثبت المستخدم في أمر README يُجلب من `main`، ويُحدّث مستقلًا عن نسخة التطبيق. يفتح `/dev/tty` لسؤال تأكيد pacman عند استخدام `curl | bash`. إذا أُلغيت العملية أو فشلت، يترك الحزمة الموثقة في `~/.cache/neura-ai/updates/` ويعيد استخدامها بعد التحقق من بصمتها بدل تنزيلها مجددًا. تظهر رسالة واضحة دون Python traceback.

تغييرات المثبت والوثائق تشغّل الاختبارات، ويُبنى المحرك الثنائي فقط عندما لا يكون إصدار `VERSION` منشورًا بالفعل.
